# PI 私人唱片店：产品与开发文档

> 文档版本：v1.0  
> 对应代码版本：PI Music Player v0.1.0  
> 文档日期：2026-08-10  
> 状态：方案评审稿，不代表已开始开发

---

## 0. 文档目的

本文将现有 **PI Music Player** 从“带 AI 的本地音乐播放器”重新定义为：

> **把硬盘里散落的歌，重新装回唱片。**

产品暂定名为 **PI 私人唱片店**。核心体验不是继续增加播放器标准功能，而是把现有的本地曲库、封面、歌词、AI 歌单和小窗能力，组织成一套有故事、有仪式感、可分享的“私人唱片收藏”体验。

本文用于统一：

- 产品定位和术语；
- MVP 范围与明确不做项；
- 页面、流程和交互要求；
- 数据模型、IPC 与服务层改造；
- AI 刻碟策略和降级方案；
- 测试、验收、风险与发布计划。

本文只制定开发方案，**不在此阶段修改现有功能代码**。

# 1. 背景与产品判断

## 1.1 参考产品带来的启发

参考产品 `burn-cd` 的传播价值主要不在播放器功能复杂度，而在于它把“搜索、试听、播放”包装成了“刻碟、放碟、等待音乐响起”的复古仪式。

可借鉴的原则：

1. **传播的是情绪和仪式，不是功能列表。**
2. **用清晰的物件隐喻降低理解成本。** CD、唱片柜和刻录台比“AI Agent”更直观。
3. **接受能力边界。** 产品不必提供完整在线曲库，也不必第一版实现所有播放器功能。
4. **输出可分享的结果。** 用户更愿意分享一张唱片封面，而不是播放器设置截图。

说明：本次环境无法成功读取参考站点页面，因此本文对参考产品的理解以用户提供的两段对话为准，不对其具体实现细节作进一步推断。

## 1.2 现有产品的问题

当前产品能力丰富，但默认表达仍然是：

```text
左侧导航 + 中间歌曲表格 + 底部播放条 + AI 聊天
```

这会产生三个问题：

- 截图看起来像普通本地播放器，缺少唯一视觉符号；
- “AI 本地智能播放器”和 BYOK 对普通用户有理解与配置门槛；
- 曲库整理、封面补全、歌词和 AI 歌单没有被统一到一个故事里。

## 1.3 新产品判断

产品的传播点应从：

> 又一个带 AI 的本地音乐播放器

调整为：

> 这个软件会把你硬盘里的旧歌整理成唱片，还能根据你的心情给你刻一张 CD。

核心动作从“创建歌单”变为“刻一张 CD”；AI 从首页聊天框退到幕后，成为“唱片店员”。

# 2. 产品定义

## 2.1 产品名称

### 暂定正式名称

**PI 私人唱片店**

### 英文副标题

**PI Private Record Store**

### 备选名称

- PI 唱片店
- Memory Disc
- After Hours Records
- 未关门唱片店

第一阶段不建议频繁更换工程包名和应用数据目录。可先仅更改界面品牌文案；待产品验证后，再决定是否修改安装包名称、`appId` 和用户数据迁移策略。

## 2.2 一句话定义

> 一款把本地音乐整理成私人唱片收藏，并能根据一句心情刻出专属 CD 的 Windows 应用。

## 2.3 核心价值

1. **找回旧歌**：把混乱文件、未知元数据和缺失封面转化为有情绪的收藏。
2. **刻一张 CD**：根据一句话从本地曲库生成有名称、有顺序、有封面的选曲。
3. **音乐属于用户**：完整歌曲始终从本地文件播放，不上传、不提供下载。
4. **可被分享**：每张 CD 都能导出不包含音频的唱片封面卡。

## 2.4 目标用户

### 核心用户

- 电脑中仍保存大量 MP3、FLAC 等本地音乐的用户；
- 对 2000—2010 年代 CD、刻录碟、千千静听、MP3 下载文化有记忆的用户；
- 不希望音乐收藏完全依赖流媒体平台的用户；
- 愿意整理旧硬盘、旧歌单和个人数字收藏的用户。

### 次要用户

- 喜欢复古 UI、数字拟物和桌面小组件的用户；
- 喜欢用 AI 生成情绪歌单，但希望音频仍保留在本地的用户。

## 2.5 非目标用户

第一阶段不重点服务：

- 只使用在线播放、没有本地曲库的用户；
- 需要跨平台云同步和移动端播放的用户；
- 需要专业音频管理、DSP、插件或发烧级均衡器的用户；
- 期待免费获取完整在线歌曲的用户。

# 3. 产品世界观与术语

统一术语可以让现有功能进入同一个故事。

| 现有名称 | 新产品名称 | 说明 |
|---|---|---|
| 添加音乐文件夹 | 打开唱片仓库 | 首次导入的主要入口 |
| 扫描本地音乐 | 清点唱片 | 扫描过程文案 |
| 曲库 | 我的唱片柜 | 默认首页 |
| 歌单 | 我的 CD / 手工选辑 | 旧歌单仍可兼容 |
| AI 助手 | 唱片店员 | 不再强调模型与 Agent |
| AI 创建歌单 | 刻一张 CD | 核心动作 |
| 补全封面 | 修复唱片封套 | 保留批处理能力 |
| 下载歌词 | 找回歌词内页 | 不强调数据源实现 |
| 重复检测 | 清点重复收藏 | 曲库管理功能 |
| 随机播放 | 店员随手挑一张 | 可作为无 AI 降级入口 |
| 桌面歌词 | 歌词投影 | 保持已有功能 |
| 小窗播放器 | 桌面唱机 | 改造现有 mini window |
| 播放历史 | 聆听档案 | MVP 后新增 |
| 分享图片 | 唱片封面卡 | MVP 必须输出 |

原则：故事化名称用于面向用户的一级界面；设置、错误详情和开发文档中仍保留准确技术术语。

# 4. 产品目标与成功指标

## 4.1 MVP 产品目标

第一版只验证一个闭环：

```text
导入本地音乐
    ↓
在唱片柜看到实体化收藏
    ↓
用一句话刻一张 CD
    ↓
播放这张 CD
    ↓
导出并分享唱片封面卡
```

## 4.2 北极星行为

**完成刻碟并导出封面卡。**

该行为同时证明用户完成了导入、理解了产品隐喻、使用了核心功能，并获得了传播素材。

## 4.3 建议指标

产品默认保持本地优先。若未来加入遥测，必须单独征得用户同意；MVP 可先用本地匿名计数供用户自己查看。

建议关注：

- 首次启动到成功导入曲库的完成率；
- 导入后 10 分钟内首次刻碟完成率；
- 刻碟成功率；
- 每张 CD 的实际播放率；
- 封面卡导出率；
- 7 日内再次打开并播放收藏的比例；
- AI 未配置时仍完成体验的比例。

建议首轮可用性目标：

- 80% 测试用户能在无指导情况下完成导入；
- 70% 能理解“刻一张 CD”等于从本地音乐生成选曲；
- 60% 能完成第一张 CD；
- 30% 愿意导出分享卡。

这些是产品验证目标，不是已经具备的数据。

# 5. 当前实现盘点

## 5.1 可直接复用的能力

现有 v0.1.0 已具备：

- Electron + React + Vite 桌面架构；
- 本地文件夹导入与音乐标签解析；
- MP3、FLAC、WAV、M4A、AAC、OGG、OPUS、WMA 扫描；
- 本地 HTTP Range 音频流与拖动播放；
- 封面提取、在线补全与本地缓存；
- LRC 歌词解析、下载和桌面歌词；
- 播放队列、播放模式、喜欢；
- 手工歌单；
- 基于 pi 的 BYOK Agent；
- 搜索曲库、创建歌单、重复检测、统计、标签等工具；
- 小窗与桌面歌词副窗口；
- Windows 安装包和 Portable 包。

## 5.2 需要新增的核心能力

- 默认首页“唱片柜”；
- 专辑/CD 实体化分组与缺失信息的故事化展示；
- “刻碟”专用流程，而不是通用聊天；
- CD 独立数据模型；
- 刻录结果的名称、选曲顺序、封面主题和内页文案；
- CD 播放器主视觉和切换仪式；
- 封面分享卡渲染与 PNG 导出；
- 数据 schema 版本和迁移；
- AI 未配置、AI 失败和小曲库情况下的本地降级策略。

## 5.3 MVP 前应处理的技术债

1. **AI 搜索分词逻辑需修正。** 当前 `normalize()` 会先删除空格，再按空格分词，容易把多个关键词合成一个长字符串，降低歌单匹配率。
2. **刻碟不能只依赖模糊关键词搜索。** 应允许 AI 返回明确的本地 `trackId` 顺序，并在服务层校验。
3. **数据存储需版本化。** 当前 `data.json` 没有 `schemaVersion`，新增 CD、历史和主题字段前应提供迁移。
4. **分享卡需要安全的本地资源读取。** 不应让渲染进程直接读取任意路径；建议沿用受控封面服务或由主进程生成导出数据。
5. **自动补封面数据源风险需隔离。** 在线失败不能阻塞唱片柜和刻碟主流程。
6. **当前播放器状态集中在 `App.jsx`。** 新增唱片柜、刻碟台和 CD 播放器后，建议拆分为播放状态 Context/Hook，避免主组件继续膨胀。

# 6. MVP 范围

## 6.1 P0：必须完成

### A. 首次开场

- 展示产品故事；
- 主按钮“打开唱片仓库”；
- 选择文件夹并扫描；
- 显示清点进度与结果；
- 空曲库时给出可理解的下一步。

### B. 我的唱片柜

- 按专辑聚合本地歌曲；
- 以 CD 盒/唱片封套网格展示；
- 点击唱片进入详情并可播放；
- 未知专辑或散曲生成“手写刻录碟”外观；
- 提供搜索和进入“曲库管理”的入口。

### C. 刻一张 CD

- 输入一句场景或心情；
- 从本地曲库生成 8—15 首有序曲目；
- 生成 CD 名称、一句店员留言和确定性封面主题；
- 展示“正在刻录”进度动画；
- 允许用户在保存前删除、调整顺序或重新生成；
- 保存后进入“我的 CD”。

### D. CD 播放器

- 显示旋转 CD、封面、曲目单和歌词入口；
- 暂停时平滑减速，播放时恢复；
- 切换 CD 时有不超过 1.2 秒的退碟/入碟动画；
- 动画不能延迟真实播放控制；
- 支持系统“减少动态效果”偏好。

### E. 分享封面卡

- 导出正方形 PNG；
- 包含名称、日期、曲目、店员留言和本地收藏标识；
- 不包含音频文件；
- 用户选择保存位置；
- 长曲目单可截断并显示“+N tracks”。

### F. 兼容入口

- 原曲库表格保留为二级“曲库管理”；
- 原设置保留；
- 原歌单数据可继续访问，允许转换成 CD 或以“旧歌单”展示；
- 桌面歌词、小窗和播放模式不回归。

## 6.2 P1：MVP 后优先

- 今日聆听收据；
- 播放历史与聆听档案；
- 唱片人格总结；
- 桌面唱机视觉升级；
- CD 封面编辑器；
- 批量修复元数据与封套；
- 从旧歌单一键制作 CD；
- “很久没听”与“入库年代”推荐；
- 多套受控 CD 视觉模板。

## 6.3 P2：验证后再做

- Apple iTunes Search API 30 秒“唱片店试听机”；
- 独立 Web 传播页；
- Web 端拖歌刻试听碟；
- Apple Music 跳转与本地曲库匹配；
- 跨设备分享元数据；
- 云端封面模板或生成式图片。

## 6.4 明确不做

MVP 不做：

- 完整在线音乐播放；
- 下载歌曲或拼接 30 秒预览；
- 社区评论、关注、点赞和动态流；
- 云同步完整音乐文件；
- 黑胶、磁带、随身听等多套物件体系；
- 专业均衡器、音效插件和复杂 DSP；
- 移动端；
- 十几种播放器皮肤；
- 强制账号系统；
- 自动上传用户曲库信息。

# 7. 信息架构

## 7.1 一级导航

建议调整为：

1. **唱片柜**：默认首页；
2. **我的 CD**：已刻录的 CD；
3. **刻录台**：核心创建入口；
4. **唱片店员**：保留完整聊天能力，但不作为主入口；
5. **曲库管理**：原表格曲库与整理工具；
6. **设置**。

窗口较窄时，可把“唱片店员”和“曲库管理”收入“更多”。

## 7.2 首页优先级

默认首页不再首先出现歌曲表格。优先显示：

- 顶部故事化欢迎语；
- “刻一张今晚的 CD”主按钮；
- 最近播放或最近刻录的一张 CD；
- 我的唱片柜；
- 缺失封面、未知元数据等待整理提示。

## 7.3 功能表面与实现层分离

用户看到：

```text
店员正在翻找唱片 → 正在排曲 → 正在写封套 → 刻录完成
```

开发日志和错误详情仍应准确显示：

```text
读取曲库 → 调用模型 → 校验 trackIds → 生成模板参数 → 保存 disc
```

不应用故事化文案掩盖真实错误。

# 8. 核心用户流程

## 8.1 首次使用

1. 启动应用；
2. 看到文案“欢迎来到你的私人唱片店”；
3. 点击“打开唱片仓库”；
4. 选择本地音乐文件夹；
5. 扫描时展示已发现歌曲数、正在读取的文件名和可取消操作；
6. 扫描完成：显示唱片数、歌曲数、缺失封套数；
7. 进入唱片柜；
8. 引导用户刻第一张 CD。

### 空状态文案

```text
这间唱片店还没有收藏。
从硬盘里找回一些旧歌吧。
```

### 未知元数据文案映射

- 无封面：马克笔手写 CD；
- 未知艺人：“从旧电脑里找到的 CD”；
- 未知专辑：“未装盒的散曲”；
- 无歌词：“歌词内页遗失”；
- 解析失败：“这张唱片暂时无法读取”。

## 8.2 刻碟流程

### 步骤 1：写下今晚

输入框示例：

- 适合凌晨两点开车听；
- 像 2012 年夏天一样；
- 下雨，但心情不坏；
- 只选很久没听的歌；
- 从周杰伦和孙燕姿里挑一张慢歌 CD。

同时提供无需输入的快捷标签：

- 深夜；
- 怀旧；
- 通勤；
- 安静；
- 随手一张。

### 步骤 2：店员选曲

界面阶段文案：

1. 正在翻找唱片；
2. 正在安排 A 面与 B 面；
3. 正在写封套；
4. 正在检查是否能播放。

允许取消。取消不能留下半成品 CD。

### 步骤 3：预览与编辑

显示：

- CD 名称；
- 店员留言；
- 曲目顺序；
- 总时长；
- 封面主题；
- “重新挑选”“换一版封套”“保存并播放”。

MVP 至少允许：

- 拖动排序；
- 删除曲目；
- 修改名称；
- 修改店员留言；
- 重新生成整张 CD。

### 步骤 4：完成

```text
CD #017 已刻录完成
《雨停之前不要回家》
```

主要操作：

- 放入唱机；
- 导出封面；
- 回到我的 CD。

## 8.3 播放流程

- 点击专辑或 CD 时先进入详情，不应仅靠双击；
- 点击“放入唱机”后立即建立播放队列；
- 视觉换碟动画与音频加载并行；
- 若音频加载更快，最多等待 300ms 让视觉建立因果感；
- 若音频加载失败，立刻停止动画并显示具体文件；
- 切歌不需要每首都执行完整退碟动画，只有切换“整张 CD”才执行。

## 8.4 分享流程

1. 在 CD 详情点击“导出封面”；
2. 选择视觉模板和明暗版本；
3. 实时预览；
4. 点击保存；
5. Electron 主进程打开保存对话框；
6. 写出 PNG；
7. 提示“封面已装袋”，并提供“打开文件位置”。

禁止默认自动发布到任何社交平台。

# 9. 页面需求

## 9.1 开场页

### 组成

- 品牌标识；
- 主标题“把硬盘里散落的歌，重新装回唱片”；
- 2—3 行产品说明；
- “打开唱片仓库”按钮；
- “先看看示例唱片”次级入口；
- 本地隐私说明。

### 验收

- 无曲库用户启动后进入开场页；
- 已有曲库用户不重复进入；
- 取消文件夹选择后界面可继续操作；
- 扫描失败不丢失已有曲库。

## 9.2 唱片柜

### 数据分组

优先以规范化后的 `album + albumArtist/artist` 分组；没有专辑信息的散曲按以下规则处理：

- 同一目录且文件数大于 1：形成“文件夹刻录碟”；
- 其余歌曲进入“未装盒的散曲”；
- 不应仅按“未知专辑”把所有未知歌曲合并成一张巨型专辑。

### 卡片信息

- 封面；
- 专辑/收藏名称；
- 艺人；
- 曲目数；
- 总时长；
- 缺失封套标记；
- 当前播放状态。

### 动效

- 悬停：CD 从盒中抽出 10%—16%；
- 点击：盒子轻微展开，进入详情；
- 当前播放：CD 低速旋转；
- 减少动态效果：只使用透明度与颜色变化。

## 9.3 刻录台

刻录台不是通用聊天页。它必须是结构化任务界面：

- 单句输入；
- 可见曲库范围；
- 曲目数量选择（8 / 12 / 15）；
- 是否排除近期常听；
- 是否优先喜欢的歌曲；
- 开始刻录；
- 进度；
- 结果编辑。

高级选项折叠，避免第一屏变成筛选器后台。

## 9.4 我的 CD

- 网格展示已保存 CD；
- 按创建时间、最近播放、名称排序；
- 支持播放、重命名、复制、删除、导出封面；
- 删除 CD 不删除本地歌曲；
- 本地歌曲被移动后，CD 标记“有 N 首唱片暂时找不到”，其余曲目仍可播放。

## 9.5 CD 播放器

### 主要视觉

- 一张透明聚碳酸酯 CD；
- 盘面印有封面色块或图片；
- 中心孔、高光、细微虹彩；
- 曲目单如歌词内页放在一侧；
- 播放进度可映射为激光头位置，但不能替代标准可访问进度条。

### 播放控制

保留：

- 播放/暂停；
- 上一首/下一首；
- 拖动进度；
- 音量；
- 播放模式；
- 喜欢；
- 歌词投影；
- 桌面唱机。

## 9.6 曲库管理

原 `LibraryView` 基本保留，负责效率，不承担传播截图：

- 表格搜索；
- 补全封面；
- 标签；
- 文件夹管理；
- 重复检测；
- 元数据问题筛选。

# 10. 视觉设计规范

## 10.1 设计方向

关键词：

- 透明塑料；
- 乳白纸张；
- 轻微磨损；
- 手写标记；
- 低饱和；
- 2000 年代数字收藏；
- 安静而非赛博朋克。

避免：

- 大量仿木纹、唱针和黑胶元素；
- 同时混用 CD、磁带、黑胶和随身听；
- 过强颗粒影响文字可读性；
- 为复古牺牲基本效率。

## 10.2 建议色板

延续现有青色品牌资产，但调整为“唱片店”材质：

```text
Paper       #F5F0E7
Plastic     #E8ECEB
Ink         #28282B
Muted Ink   #727278
Teal        #3BA8A0
Teal Deep   #247C76
Laser Pink  #D98AA6
Warning     #B66A4A
```

现有浅色主题可以作为“曲库管理模式”；唱片柜可采用偏暖纸张背景。

## 10.3 字体

- 中文正文：系统字体优先，保证安装包体积和可读性；
- 数字与编号：等宽字体栈；
- 手写效果：MVP 不打包未知授权字体，优先用系统手写字体回退，或使用 SVG 路径资产；
- 分享卡导出前必须确认字体授权和跨机器一致性。

## 10.4 缺失封面模板

缺失封面不是灰色占位块，而是确定性生成：

- 由 `track/album key` 计算颜色种子；
- 显示手写标题、艺人或文件夹名；
- 添加 `CD-R 80 MIN`、编号和日期等装饰；
- 相同收藏每次渲染结果一致；
- 不需要模型和网络。

## 10.5 动效预算

- 悬停：120—180ms；
- 唱片抽出：240—360ms；
- 完整换碟：800—1200ms；
- 刻录完成：600—900ms；
- 常驻旋转使用 GPU 友好的 `transform`；
- 不对大面积模糊、阴影和滤镜做持续动画。

# 11. AI 刻碟设计

## 11.1 AI 的角色

AI 不直接作为聊天机器人出现，而作为“唱片店员”完成四件事：

1. 理解用户场景；
2. 在真实本地歌曲中选曲；
3. 安排顺序；
4. 生成名称和一句短文案。

封面图形本身在 MVP 使用本地确定性模板，不依赖图片生成模型。

## 11.2 输入

提交给模型的内容应最小化：

- 用户提示词；
- 用户选择的目标曲目数；
- 候选曲目的 `id/title/artist/album/year/genre/tags/liked`；
- 可选的本地播放统计摘要；
- 输出 JSON schema。

默认不提交：

- 音频文件；
- 文件绝对路径；
- API Key；
- 与任务无关的完整聊天历史。

## 11.3 输出 schema

建议模型只返回结构化结果：

```json
{
  "title": "雨停之前不要回家",
  "note": "这些歌不是关于下雨，而是关于那些没有说出口的话。",
  "trackIds": ["local-track-id-1", "local-track-id-2"],
  "theme": {
    "template": "handwritten-cdr",
    "palette": "rain-teal",
    "accent": "#3BA8A0"
  },
  "reason": "深夜、安静、怀旧，前半段舒缓，后半段逐渐明亮"
}
```

服务层必须：

- 删除不存在的 `trackId`；
- 去重；
- 限制曲目数量；
- 限制标题和留言长度；
- 对颜色和模板使用白名单；
- 如果有效曲目过少，走重试或降级，不保存空 CD。

## 11.4 选曲策略

不建议把整个大型曲库直接发给模型。建议两阶段：

### 阶段 A：本地召回

按以下字段打分并召回最多 100—200 首：

- 标题、艺人、专辑、风格、年份、标签；
- 喜欢状态；
- 最近播放与很久没听；
- 用户明确点名的艺人或年代。

### 阶段 B：模型编排

模型从候选中选择 8—15 首并排序，返回明确 `trackIds`。

### 顺序要求

- 避免连续出现过多同艺人歌曲，除非用户明确要求；
- 开场曲、情绪推进和收尾曲有可解释顺序；
- 同一文件不重复；
- 不得编造本地不存在的歌曲。

## 11.5 无 AI 降级

BYOK 是当前转化门槛，因此核心体验不能完全被 API Key 阻断。

未配置模型时：

- 仍可使用“随手刻一张”；
- 使用本地标签、年份、喜欢和随机权重选曲；
- 名称来自本地模板，如“午夜收藏 #012”；
- 留言使用模板文案；
- 在结果页提示“配置唱片店员后，可理解更具体的心情描述”。

AI 超时或返回非法结果时：

1. 自动进行一次结构化重试；
2. 仍失败则询问用户是否使用本地规则完成；
3. 不显示空白结果，不丢失用户输入。

## 11.6 Prompt 原则

系统提示应强调：

- 只使用提供的本地曲目；
- 只返回合法 JSON；
- 不做心理诊断；
- 文案短、克制，不堆砌伤感句式；
- 用户请求与曲库不匹配时诚实说明；
- 不暗示应用拥有歌曲版权。

# 12. 数据模型与迁移

## 12.1 存储版本

为 `data.json` 增加：

```json
{
  "schemaVersion": 2
}
```

迁移规则必须满足：

- 迁移前创建备份；
- 迁移幂等；
- 失败后可回退；
- 不删除原曲库、歌单和设置；
- API Key 现有存储方式另行进行安全评估，不在此次迁移中静默改变。

## 12.2 Disc 模型

```ts
type Disc = {
  id: string;
  serial: number;
  title: string;
  note: string;
  prompt: string;
  trackIds: string[];
  source: "ai" | "local-rule" | "manual" | "playlist-import";
  theme: {
    template: "handwritten-cdr" | "jewel-case" | "minimal-label";
    palette: string;
    accent: string;
    coverTrackId?: string;
  };
  createdAt: number;
  updatedAt: number;
  lastPlayedAt?: number;
  playCount: number;
};
```

## 12.3 AlbumViewModel

专辑分组建议只在运行时计算，不必立即重复持久化：

```ts
type AlbumViewModel = {
  key: string;
  title: string;
  artist: string;
  trackIds: string[];
  coverId?: string;
  totalDuration: number;
  kind: "album" | "folder-disc" | "loose-tracks";
  metadataState: "complete" | "missing-cover" | "missing-metadata";
};
```

## 12.4 播放历史（P1）

```ts
type PlayEvent = {
  id: string;
  trackId: string;
  discId?: string;
  startedAt: number;
  listenedSeconds: number;
  completed: boolean;
};
```

播放事件应做聚合和定期清理，避免 JSON 无限增长。若历史量增大，再迁移 SQLite；MVP 不必提前引入数据库。

## 12.5 分享卡快照

建议分享卡使用当前 Disc 数据即时生成，不默认保存冗余图片。用户显式导出后再写入所选位置。

- 主进程 Store：曲库、CD、设置；
- IPC 后刷新服务端真值。

避免把所有状态继续堆入 `App.jsx`。

## 13.4 资源渲染

CD 盘面和分享卡优先使用：

- HTML/CSS + SVG；
- Canvas 或 SVG 序列化导出；
- 本地确定性纹理；
- 受控封面 URL。

不建议 MVP 引入 Three.js。2D CSS/SVG 足以完成旋转、虹彩和抽碟效果，包体与维护成本更低。

# 14. IPC 设计

建议在 preload 中新增窄接口，不暴露文件系统通用能力。

```ts
window.api.discs.list()
window.api.discs.get(id)
window.api.discs.create(input)
window.api.discs.update(id, patch)
window.api.discs.delete(id)
window.api.discs.fromPlaylist(playlistId)

window.api.burn.create(request)
window.api.burn.cancel(jobId)
window.api.burn.onProgress(callback)

window.api.export.saveDiscCard({ discId, template, imageData })
window.api.export.openContainingFolder(path)
```

## 14.1 `burn.create` 请求

```json
{
  "prompt": "适合凌晨两点开车听",
  "trackCount": 12,
  "preferLiked": false,
  "avoidRecent": true,
  "mode": "auto"
}
```

## 14.2 进度事件

```json
{
  "jobId": "burn_xxx",
  "stage": "recall | arrange | artwork | validate | done | error",
  "progress": 0.65,
  "message": "正在安排最后一首歌"
}
```

## 14.3 安全要求

- 渲染端不能传任意输出路径直接写文件；必须走保存对话框；
- `trackIds` 必须在 Store 中存在；
- 分享图片数据限制大小；
- IPC 参数进行类型、长度和白名单校验；
- 取消任务需要使用 `AbortController` 或 Agent abort；
- 不把绝对音乐路径发给模型。

4. 店员留言；

- 具体艺人名；
- 具体曲目名；

# 16. 在线 30 秒试听机（P2）

## 16.1 定位

如果接入 Apple iTunes Search API，功能应被定义为：

> 唱片店试听机：搜索并播放数据源提供的官方短预览。

不应称为“完整在线播放”或“已经解决音乐版权问题”。

## 16.2 建议流程

```text
在线搜索
  ↓
播放官方短预览
  ↓
在本地曲库查找是否已有
  ↓
已有：播放本地完整文件
没有：加入“想找的唱片”或跳转官方页面
```

## 16.3 合规要求

正式接入前必须复核 Apple 当时有效的开发者条款。原则上至少做到：

- 不缓存或二次分发预览音频；
- 不拼接多个片段模拟完整歌曲；
- 标注数据来源；
- 提供对应官方页面跳转；
- 遵守预览内容、归属标识和展示场景要求；
- 搜索、播放失败时不切换到来源不明的兜底音频；
- 在隐私说明中披露请求会发送给第三方服务。

本文不是法律意见。上线前应进行条款与法务复核。

## 16.4 为什么不进入桌面 MVP

- 本地曲库已经能形成完整闭环；
- 在线入口会增加网络、条款、地区和可用性风险；
- 容易让用户误解产品变成在线音乐服务；
- 会分散对“整理自己的收藏”这一核心叙事的注意力。

# 17. 隐私、版权与安全

## 17.1 本地优先原则

- 音频文件始终保留在用户电脑；
- 应用只建立本地索引；
- AI 刻碟默认只发送必要的文本元数据；
- 分享卡只由用户主动导出；
- 不默认启用行为遥测。

## 17.2 第三方服务披露

设置页应列明实际使用的服务及用途：

- 用户配置的大模型服务：理解提示与编排曲目；
- Lrclib / 其他歌词来源：查询歌词；
- 封面来源：查询封面；
- ACRCloud：哼唱识别；
- Apple API（若未来接入）：搜索和短预览。

应区分“本地功能”和“会访问网络的功能”。

## 17.3 版权表达

产品文案统一：

> 本应用管理并播放用户本地已有的音乐文件，不提供音乐下载或完整在线曲库。

不使用：

- “无版权限制”；
- “彻底解决版权”；
- “免费听全网音乐”；
- 暗示拥有第三方专辑封面和歌词再分发权的表述。

## 17.4 API Key

当前应用将 BYOK 配置写入应用数据目录。发布新版本前应评估：

- 使用 Electron `safeStorage` 加密 Key；
- 日志和错误信息中永不输出完整 Key；
- 导出设置不包含 Key；
- 卸载与重置时给出清理凭据选项。

# 18. 性能与可访问性

## 18.1 性能目标

- 1,000 首曲库进入唱片柜后 2 秒内可交互；
- 10,000 首曲库使用虚拟列表或分段渲染；
- 唱片柜首屏只加载可见封面；
- CD 常驻旋转不造成明显 CPU 占用；
- 分享卡导出期间 UI 不冻结超过 200ms；
- 扫描、AI 和导出任务均可取消。

## 18.2 可访问性

- 所有核心操作可用键盘完成；
- CD 视觉不能替代标准播放按钮和文本；
- 文本对比度达到 WCAG AA 的合理目标；
- 不仅依赖颜色表示当前播放或错误；
- 支持 `prefers-reduced-motion`；
- 动画闪烁频率受控；
- 分享卡预览有可读文本说明。

# 19. 错误与降级设计

| 场景 | 用户提示 | 行为 |
|---|---|---|
| 曲库为空 | “唱片仓库还是空的” | 引导导入 |
| 曲库少于目标曲目数 | “目前只找到 N 首合适的歌” | 允许少量完成或放宽条件 |
| AI 未配置 | “店员还没接入，但可以先随手刻一张” | 本地规则降级 |
| AI 超时 | “店员翻找得太久了” | 重试或本地完成 |
| AI 返回不存在歌曲 | 不暴露模型幻觉细节 | 服务端过滤并重试 |
| 封面下载失败 | “封套暂时没有找到” | 使用手写 CD 模板 |
| 本地文件移动 | “这首唱片暂时找不到” | 跳过并提供重新扫描 |
| 导出失败 | 显示可操作原因 | 重选目录或降低尺寸 |
| 歌词不存在 | “歌词内页遗失” | 不影响播放 |
| 网络离线 | “唱片店进入离线营业” | 本地播放、管理、规则刻碟可用 |

原则：网络能力失败不能让本地音乐无法播放。

# 23. 发布策略

## 23.1 首发版本建议

版本可命名为：

**PI 私人唱片店 0.2.0 — First Pressing**

“First Pressing”只作为发布主题，不影响语义化版本。

## 23.2 发布页只讲三个卖点

```text
找回旧歌
把硬盘里的本地收藏重新整理成唱片。

刻一张 CD
写下一句话，让唱片店员从你的曲库里选出今晚的歌。

音乐属于你
完整歌曲始终保留在你的电脑里。
```

## 23.3 演示素材

发布演示应展示一个 15—25 秒闭环：

1. 文件夹导入；
2. 唱片墙出现；

当前 Windows 包未签名，SmartScreen 会影响传播。发布前的现实选择：

- 同时提供 Portable ZIP；
- 发布页说明本地数据和网络访问范围；
- 不用“关闭安全软件”等高风险文案引导用户。

# 24. 风险清单

| 风险 | 影响 | 应对 |
|---|---|---|
| 视觉很复古但使用低效 | 留存下降 | 唱片柜负责情绪，曲库管理负责效率 |
| AI/BYOK 门槛高 | 首次刻碟失败 | 本地规则降级，AI 配置后置 |
| AI 编造歌曲 | 信任受损 | 只接受真实 trackIds，服务端强校验 |
| 曲库标签很差 | 选曲质量低 | 本地召回结合文件夹、喜欢和用户标签；诚实提示 |
| 动画拖慢播放 | 核心体验受损 | 视觉与音频并行，设最大等待时间 |
| 在线封面/歌词不稳定 | 页面缺失 | 手写封套和“歌词内页遗失”降级 |
| 分享卡泄露隐私 | 严重 | 禁止路径、电脑名；导出前预览 |
| JSON 数据膨胀或损坏 | 收藏丢失 | schema、备份、原子写入、迁移测试 |
| 多套视觉导致范围失控 | 延期 | MVP 仅 CD，分享模板仅两套 |
| 误导性版权宣传 | 合规与声誉风险 | 明确本地播放器定位；在线预览另行审查 |
| 未签名安装包 | 下载转化低 | SHA256、Portable、后续签名 |

9. 是否在 0.2.0 投入 Windows 代码签名；

- 名称：采用“PI 私人唱片店”；
- 在线试听：不进入 MVP；

- 遥测：MVP 默认关闭。

# 26. Definition of Done

MVP 只有在以下条件全部满足后才算完成：

- [ ] 新用户能从开场页完成本地曲库导入；
- [ ] 默认首页是唱片柜而非普通歌曲表格；
- [ ] 无封面和未知元数据有完整的故事化降级；
- [ ] 用户能用一句话生成一张只包含真实本地歌曲的 CD；
- [ ] 未配置或调用 AI 失败时仍能完成本地规则刻碟；
- [ ] 用户可编辑名称、留言和曲目顺序；
- [ ] CD 可保存、重启恢复、播放和删除；
- [ ] CD 播放器有明确实体感，但动画不阻塞控制；
- [ ] 用户能导出不包含音频和本地路径的 PNG 封面卡；
- [ ] 原本地播放、歌词、小窗、搜索、歌单和设置没有关键回归；
- [ ] v0.1.0 数据迁移有备份且通过测试；
- [ ] 大曲库、损坏文件、离线和缺失封面场景可用；
- [ ] 隐私、版权与第三方服务说明已更新；
- [ ] Windows 安装版和 Portable 包均完成验证。

# 27. 最终结论

本项目不需要推翻现有播放器重做。最合理的策略是：

1. 保留现有本地播放和管理能力作为底座；
2. 把默认首页从歌曲表格改成唱片柜；
3. 把 AI 歌单改造成结构化“刻碟”流程；
4. 增加 CD 独立数据和实体化播放器；
5. 用封面卡完成传播闭环；
6. 把在线 30 秒试听、聆听收据和唱片人格留到验证之后。

第一版最重要的不是功能数量，而是让用户稳定完成这一句话：

> **我把硬盘里的旧歌找了回来，还为今晚刻了一张 CD。**
